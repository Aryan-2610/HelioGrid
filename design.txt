Backend Behavior: Zero cache lookup—immediately forwards (lat, lon) to Step 5.Step 5: Backend → ISRO VEDAS Solar Data APIISRO SAC's VEDAS (Visualisation of Earth Observation Data and Archival System) computes India's solar potential ($\text{kWh/m}^2$) from Indian geostationary satellites (Kalpana / INSAT-3D) paired with Cartosat DEM terrain shadow data, and exposes programmatic access through the VEDAS API Centre ([https://vedas.sac.gov.in/vconsole/](https://vedas.sac.gov.in/vconsole/)) using GeoServer OGC WMS and Temporal APIs (free API key after registration).How You Query a Single Point on OGC WMS (GetFeatureInfo): Construct a tiny bounding box around (lon, lat)—e.g., [lon - 0.001, lat - 0.001, lon + 0.001, lat + 0.001]—and request the pixel value at the center (X=50, Y=50) of a 101×101 virtual tile in JSON format:HTTPGET https://vedas.sac.gov.in/<vedas_solar_wms_endpoint>?SERVICE=WMS&VERSION=1.1.1&REQUEST=GetFeatureInfo&LAYERS=<solar_insolation_layer>&QUERY_LAYERS=<solar_insolation_layer>&SRS=EPSG:4326&BBOX=77.1170,28.7485,77.1190,28.7505&WIDTH=101&HEIGHT=101&X=50&Y=50&INFO_FORMAT=application/json&API_KEY=<YOUR_VEDAS_KEY>
(You copy the exact WMS service path and layer name—such as INSAT GHI or WRF Solar Insolation—from the VEDAS API Centre's Samples / GetCapabilities page after signing up.)Get Back (Standard GeoServer GetFeatureInfo GeoJSON):JSON{

Practical Implementation Notes for ISRO APIsAPI Key / Token Expiry: VEDAS API Centre issues a developer key on registration, whereas Bhuvan REST API access tokens expire every 24 hours—so keep Nominatim for geocoding in V1 to avoid regenerating tokens daily.Isolate Step 5 in One Function: Wrap the WMS GetFeatureInfo request inside a single fetch_ghi(lat, lon) Python function. If a specific VEDAS GeoServer layer is temporarily down for maintenance during a live demo, you can swap the URL inside that one function (or fall back to a static state-wise INSAT GHI lookup dictionary) without touching any other code.
